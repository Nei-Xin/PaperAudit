# PaperAudit 论文学习与证据审计

> 犀牛鸟开源实战任务个人作品，非腾讯官方项目。

PaperAudit 是一个本地优先的英文 AI 论文学习、论文与代码联合阅读、报告证据审计工具。它把 PDF 原文、结构化讲解、代码索引、追问记录和审计历史保存在同一个项目工作区中，帮助用户从“读懂论文”走到“核对结论”和“导出可提交报告”。

当前演示主线是：**上传论文 → 生成讲解 → 可选关联代码 → 追问与定位证据 → 审计报告 → 导出 Markdown/JSON/PDF**。

这是一个面向英文 AI 论文的中文学习与证据审计应用。用户可以生成结构化论文讲解、联合阅读论文与代码，也可以上传已有报告，逐条核验报告内容是否得到论文原文支持。当前实验与演示使用可配置的 Hy3 模型；模型名称、服务地址和密钥均通过本地环境变量配置。

## 任务一定位

**目标用户**是需要阅读、汇报或复核英文 AI 论文的本科生、研究生、科研新人和工程开发者。

他们面对的核心问题不是“生成一段摘要”，而是论文篇幅长、术语密集，AI 讲解又可能出现数字错误、遗漏实验条件、夸大结论或伪造引用。PaperAudit 将论文讲解与证据审计放在同一工作区，让用户能从中文结论回到 PDF 原文核验，并对已有报告逐条检查。

该场景需要大模型理解跨段落语义、拆分原子论断、生成检索查询并判断论断与证据的支持关系；仅靠关键词规则无法可靠处理改写、条件限定和结论强度。配置的大模型负责语义理解与结构化判断，本地程序负责 PDF 解析、候选检索、页码与代码行定位、引用白名单校验和确定性评分，避免让模型自行伪造证据位置。

## 当前能力

- 上传带文本层的英文论文 PDF；
- 首次启动时选择本地项目保存目录，后续自动恢复该配置；
- 自动保存论文、解析索引、结构化讲解、代码索引和追问历史；
- 通过 URL 项目 ID 和首页“最近阅读”在刷新后继续已有项目；
- 支持“模拟投稿评审”：从研究价值、创新性、技术可靠性、实验充分性、清晰度和可复现性六个维度评分，并给出 Strong Accept / Weak Accept / Borderline / Weak Reject / Strong Reject 五档预审建议；
- 评审意见包含主要问题、次要问题和优先修改事项，关键判断绑定可回到 PDF 的原文证据；
- 评审会显式区分事实、推断和证据不足，并展示文本评审边界；离线质量门禁检查论文级隔离、证据有效性、严重度和 P1 漏报率；
- 支持问题复核、AI 原始判断与用户修订值对比、P3 批量忽略和“需人工复核”筛选；
- 支持轻量修改稿对比：保存新版本评审、显示评分变化以及已消失、仍存在和新增问题；
- 评审标准带有 rubric 版本、更新时间、标准说明和权重快照，自定义权重会生成稳定版本指纹；
- 模拟评审在单进程后台队列执行，提交后可继续使用页面；结果和任务状态会保存到左侧论文项目，刷新后可恢复查看；
- 上传完成后立即显示可翻页的无高亮 PDF 原文预览；
- 使用配置的模型生成结构化中文讲解，覆盖研究问题、核心贡献、方法、实验、结果、局限性和关键术语；
- 关键知识点绑定本地解析得到的真实论文证据；
- 通过章节切换、左侧 PDF 原文和右侧讲解联动阅读；
- 采用 PDF 主视图与 AI 辅助侧栏布局，并支持一键进入专注阅读；
- 仅在用户点击知识点或回答引用后切换页面并高亮原文位置；
- 在右侧 PDF 中拖选文字或点击单词，携带页码与匹配 Chunk 发起追问；
- 针对当前论文继续追问，回答引用经本地校验的原文 Chunk；
- 证据不足时明确拒绝补全，并保留最近 10 轮论文内对话；
- 可选上传论文开源代码 ZIP；未上传代码时保持原有纯论文流程；
- 安全解析 Python、Markdown、YAML、JSON、TOML 和 Shell 文本，不执行代码或安装依赖；
- 建立包含仓库相对路径、符号名和起止行号的内存代码索引；
- 在“论文与代码”工作区并排查看可选文字的 PDF 与带行号代码；
- 支持仅论文、仅代码及论文与代码联合追问，回答范围也可自动判断；
- 论文引用绑定真实页码与 Chunk，代码引用绑定真实文件与行号，模型引用均经本地校验；
- 可从论文选中文字查找对应实现，并由回答引用跳转到 PDF 或代码上下文；
- 导出讲解 Markdown 和结构化 JSON；
- 粘贴或上传 `.txt`、`.md` 中文报告进行审计；
- 单次审计报告最多 100,000 个字符，超长报告需拆分后处理；
- 在已保存的论文工作区中，可直接审计当前讲解，或上传 `.txt`、`.md` / 粘贴另一份报告并复用当前论文原文；
- 工作区审计进入单进程后台队列，同一时间执行一个任务，其余任务等待，提交后可继续阅读或切换论文项目；
- 后台任务状态与完整审计结果保存到对应论文项目，刷新页面或重新打开项目后仍可查看多次审计历史；
- 将报告拆成原子论断并生成英文检索查询；
- 抽取前固定原文句子编号，分批核对每句的论断或跳过原因；论断保留原文摘录与位置，漏项或无效来源重试后仍未通过则停止本次审计；
- 句末引用与原句一起保留，由本地程序补回原报告引用并检查越界页码；审计结果范围包含在哪些数据或任务上开展评估的事实；
- 高风险“未找到支持”结论最多补查一次，优先检索报告引用页并补充至多五个候选片段；证据仍不足或复核结果无效时转为人工复核；
- 基于 SQLite FTS5 的本地候选证据检索；
- 论断级支持判断、错误分类、风险分级和修改建议；
- 六维摘要、自动审计覆盖率和可信等级；
- 导出审计 Markdown 和 JSON。

当前版本不支持扫描件 OCR、复杂表格可靠解析、自动修订、跨论文或联网问答、公式证明、图片理解、跨论文事实核验或参考文献真实性检查。代码能力不执行仓库、不安装依赖、不复现实验，也不支持 GitHub URL、私有仓库、多仓库比较或 Java/C++ 精细语法分析。后台审计只在当前 Streamlit Python 进程运行期间执行；关闭应用或电脑后不会继续，重启时未完成任务会标记为中断。第一版不支持任务强制取消、并行审计、Word/报告 PDF 上传，也不会把没有关联到已保存论文项目的临时审计写入项目历史。

模拟投稿评审是基于单篇论文原文的 AI 辅助预审建议，不等同于真实会议录用预测；它不会可靠判断领域内绝对创新性、最新 SOTA、论文造假或目标会议竞争强度。修改稿问题匹配为轻量一对一匹配，低置信结果需要用户确认。

## 方向一评测

评测对象是论文讲解或报告中的原子论断。系统使用“本地检索 + 配置的模型判断 + 确定性规则 + 人工标注”的半自动方案，输出六个 0–100 分维度：事实支持度、证据正确性、证据完整性、数字与指标一致性、内容覆盖度和结论边界。支持标签、错误类型、风险等级和各维度计算方式均有可执行定义。

当前固定评测累计覆盖 28 篇论文、264 条原子论断；最终独立留出集包含 6 篇新论文、48 条样本。冻结版本在最终留出集上的标签准确率为 83.33%、错误类型准确率为 78.79%、风险准确率为 83.33%、Top-5 证据召回率为 87.50%。40 条固定样本重复调用真实 API 三次的标签两两一致率为 98.33%；10 组成对对抗样本未出现标签变化、评分上升或风险降低。

上述结果证明当前证据审计主流程具有可用的区分能力与自动运行稳定性，但不等于已经完成独立人工双评审一致性。现有好/中/差结果是评分汇总层探针，不应表述为多篇自然完整报告的端到端排序。模拟投稿评审属于实验性辅助功能，其冻结留出集建议一致率仍偏低，不作为论文真实录用概率。

## 当前正式实验

当前提交包采用 hy3 完成方向一的正式实验：96 次审计任务中 93 次成功、3 次因接口响应错误失败；93 份成功结果完成语义对齐。实验保留原始输入、模型响应、逐请求检查点、失败记录、协议修订、统计文件和最终报告

报告中的“人工标注”是按项目协议记录的参考标注，实际由模型辅助生成；它不等同于独立人工双评审金标准。详细数字、阶段成功率、耗时和限制请以 [最终验收报告](docs/final_acceptance_report.md) 与 [提交报告](eval/hy3_reliable_20260907/submission_report.md) 为准。

## 环境要求

- Python 3.11+
- 可用的模型 API 地址、密钥和模型名称
- 推荐使用 `uv`

## 安装

```powershell
uv sync --dev
Copy-Item .env.example .env
```

编辑本地 `.env`：

```env
HY3_API_BASE=https://your-hy3-api.example/v1
HY3_API_KEY=your-local-key
HY3_MODEL=hy3
```

`.env` 已加入 `.gitignore`，不得提交真实 API Key。

## 运行

```powershell
uv run streamlit run app.py
```

首次打开会要求选择本地项目保存目录。应用只在固定的本机设置文件中记录该目录，不会把 API Key 写入项目文件。

## 测试

```powershell
uv run python -m pytest -q
```

使用 `python -m pytest` 可确保项目根目录进入模块搜索路径，评测脚本测试能够稳定导入顶层 `eval` 包。

核心审计修改可用独立构造的开发样例验证（调用当前配置的 API，重复三次）：

```powershell
uv run python -m eval.check_core_audit_dev
```

结果写入 `eval/core_audit_dev_check.json`，覆盖原文拆分、虚构数字、无依据的最优性证明，以及正确数值、适用范围和真实定理的对照。该开发检查不使用或覆盖冻结留出集，也不代表完整报告的泛化准确率。界面与导出中的非弃权比例仅针对已抽取论断；逐句返回核对与被模型跳过的原文单独展示，不能据此宣称报告事实已全部抽取。

引用、范围和高风险误报修复的定向真实 API 检查入口为 `uv run python -m eval.check_core_repairs`，使用上一轮暴露问题的三份报告各运行一次，结果保存在 `eval/core_repairs_20260905/`；已有结果不会被覆盖。这是已知失败样例的开发回归，不替代三次重复一致性或独立留出集验证。

## 数据说明

PDF 和可选源码 ZIP 均在本地解析。学习项目按 PDF 哈希保存在用户首次选择的目录中，包括原始 PDF、论文索引、结构化讲解、可选代码索引、追问历史、后台审计任务和审计历史；写入采用临时文件与原子替换。审计历史保留被审计报告快照、内容哈希、结果和非敏感运行配置，同一项目可以保存多次审计；API Key 和 API Base URL 不进入任务或审计记录。生成讲解时，模型只选择候选 Chunk ID，页码和原文由本地论文索引补齐。代码与联合问答中，Hy3 同样只能选择候选代码块 ID，文件路径和行号由本地索引补齐；不存在的引用会被丢弃。论文与代码检索过程仍使用内存 SQLite FTS5。源码 ZIP 有文件数量、压缩包大小、可读文本总量和单文件大小限制，并忽略常见密钥、虚拟环境、构建产物和模型权重目录。
