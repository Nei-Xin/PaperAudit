- 鼠标拖选代码并在右栏提问；

## 五、P0-1：代码索引版本与自动升级

### 数据模型

在 `ParsedCodebase` 中加入：

```python
index_version: int = 1
```

要求：

- 默认值为 `1`，确保旧 `codebase.json` 可以直接读取；
- 在代码解析模块定义当前版本常量，例如：

```python
CURRENT_CODE_INDEX_VERSION = 2
```

- `parse_code_zip()` 新生成的索引写入当前版本；
- 不修改整个项目存储 schema，仅升级代码索引自身。

### 重建函数

在 `code_parser.py` 提供一个公开、纯本地函数，例如：

```python
def rebuild_code_index(codebase: ParsedCodebase) -> ParsedCodebase:
    ...
```

要求：

- 只使用已保存的 `codebase.files`；
- 不需要原 ZIP，不联网，不执行源码；
- 复用现有 `_chunks_for_file()` 规则；
- 重新分配稳定的 `c00001` 形式 chunk ID；
- 保留仓库名称、文件内容和原解析警告；
- 更新 `index_version`；
- 相同输入应得到相同 chunk 顺序和 ID。

### 存储升级

在加载项目代码索引时：

1. 先正常解析旧 `codebase.json`；
2. 若 `index_version < CURRENT_CODE_INDEX_VERSION`，调用重建函数；
3. 重建成功后原子写回该项目的 `codebase.json`；
4. 本次会话使用升级后的对象；
5. 下次打开不重复写入；
6. 升级失败时不破坏旧文件，并返回明确但可恢复的错误。

不要：

- 要求用户重新上传 ZIP；
- 修改论文 PDF、讲解报告、审计记录或历史消息；
- 因升级代码索引而清空问答历史；
- 在每次 Streamlit rerun 时重复重建。

## 六、P0-2：方法级 Python 切块完善

期望结构示例：

```text
MaskData                 L16–20   类声明、文档字符串和类级属性
MaskData.__init__        L21–28
MaskData.filter          L44–57
MaskData.cat             L59–70
MaskData.to_numpy        L72–75
```

规则：

- 顶层函数维持独立 chunk；
- 类方法和异步类方法始终独立 chunk；
- 方法装饰器应包含在方法 chunk 中；
- 类装饰器应包含在类级 chunk 中；
- 没有方法的类可以保留整个类 chunk；
- 类级 chunk 只保存首个方法之前的类声明、文档字符串和类级内容；
- 不为了覆盖极少见 AST 结构进行复杂递归重构；
- 语法错误仍按固定行块降级。

第一版不处理嵌套类和函数内部定义的局部函数索引。

## 七、P0-3：选区引用的服务端约束

已有逻辑会保留真实 chunk ID，同时把候选的展示范围缩小到用户选区。继续补充以下约束：

### 代码解释模式

当满足以下条件时：

- `selected_code` 非空；
- 回答范围为 `CODE`；
- 回答状态为 `ANSWERED`；

最终有效引用中必须至少包含一个与用户选区重叠的真实 chunk ID。

如果模型只引用无关候选：

- 不得把无关代码作为选区解释的依据；
- 将结果降级为 `INSUFFICIENT_EVIDENCE`，或返回明确的“模型未引用选中代码”；
- 不要静默伪造或自动补上一条模型没有使用的引用。

### 论文—代码对应模式

`JOINT` 模式允许同时引用：

- 用户选中的代码 chunk；
- 论文证据；
- 为解释调用关系而检索到的其他代码 chunk。

但只要回答声称解释了选中代码，至少一条代码引用必须来自选区重叠 chunk。

### 精确展示范围

底层引用继续使用真实 chunk ID；前端展示范围按以下优先级：

```text
该消息绑定的用户选区
    ↓
方法级 CodeCandidate / CodeCitation
    ↓
类级或固定行块
```

历史消息点击引用时，不得使用当前全局选区覆盖该消息自己的选区快照。

## 八、P0-4：历史记录和旧引用兼容

必须兼容：

- 旧历史消息没有 `selected_code` 字段；
- 旧历史引用使用旧 chunk ID；
- 新索引重建后 chunk ID 可能与旧索引含义不同。

最简单安全策略：

- 历史消息中的 `CodeCitation` 已保存路径、行号和文本，页面定位优先使用这些字段；
- 不用新索引重新解释或改写旧历史回答；
- 若旧引用路径仍存在且行号合法，继续允许定位；
- 若路径不存在或行号越界，显示“历史引用当前无法定位”，不要跳到错误文件；
- 新问题只使用升级后的新索引。

不要设计复杂的旧 chunk ID 映射数据库。
