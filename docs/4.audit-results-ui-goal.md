# 审计结果工作台 UI 优化：`/goal` 执行文档

> 文档用途：供 Codex `/goal` 在用户离开期间自主执行。  
> 当前项目：Hy3 论文学习助手（Streamlit）  
> 本轮目标：将当前冗长、全部展开的审计结果页改造成便于快速发现问题、逐条核验证据的紧凑审计工作台。  
> 实施原则：只调整结果页的信息架构、组件和样式；不修改审计 Prompt、检索、判断、评分、持久化或后台任务逻辑。

## 一、可直接用于 `/goal` 的任务描述

```text
按照 docs/4.audit-results-ui-goal.md 完成“审计结果工作台 UI 优化”第一版开发。

要求：
1. 将当前大面积的等级卡片和六个 Metric 压缩为一条紧凑结果摘要，突出可信等级、总分、覆盖率、证据发现率、严重和高风险数量。
2. 逐条审计默认按风险优先排序，并提供“需关注 / 全部 / 冲突 / 未找到证据 / 证据不足”等快速筛选；保留分类、风险等级和关键词筛选能力。
3. 不再默认展开全部论断。每条论断使用紧凑折叠行，折叠状态至少显示论断编号、分类、论断摘要、判定标签和风险等级。
4. 展开单条论断后再展示完整论断、判断说明、修改建议和原文证据；没有修改建议或证据时不渲染空区域。
5. 原文证据只在展开后显示，并将 PDF 抽取得到的多余换行和连续空白仅在 UI 展示层折叠为空格，不能修改持久化数据或导出内容。
6. 多条证据采用紧凑编号列表，清楚显示页码和 Chunk ID；长证据保持可读宽度，不再出现文字挤在左侧、右侧大片空白的情况。
7. 清楚显示当前筛选结果数量以及“正常 / 需关注”分布；筛选无结果时显示可理解的空状态和“清除筛选”。
8. 保留六维分析、风险统计、Markdown/JSON 导出、历史审计来源提示和“返回论文讲解”功能。
9. 桌面端优先保证 1280px、1440px 和 1920px 宽度可用；窄屏下筛选器自动换行，不能出现横向溢出。
10. 复用现有 AuditRun、ClaimAudit 和标签映射，不增加数据库、模型调用或新的审计字段。
11. 增加聚焦测试，覆盖筛选、排序、证据展示文本清理和无证据情况；运行全部测试、编译检查和本地浏览器视觉验证。
12. 修复真实阻塞问题后停止，不顺手重构其他论文阅读、代码阅读、追问或后台审计模块。
```

## 二、当前问题

当前“逐条论断审计”页面一次展开全部论断和全部证据，30 条论断会形成很长的页面。截图中的主要问题是：

- 正常支持项和严重问题拥有相同的大卡片，用户无法快速找到需要处理的内容；
- 每条论断默认显示完整判断和所有证据，纵向滚动成本很高；
- PDF 双栏文本抽取保留了硬换行，证据文字被压成左侧窄列，卡片右侧出现大面积无效空白；
- 判定与风险标签位于卡片最右侧，和论断编号、分类、正文之间距离过远；
- 总体结论、六个指标、三个页签、四个筛选器层级较多，首屏信息密度低；
- 用户最关心的是“有哪些问题、为什么、对应什么证据、如何修改”，但当前页面首先呈现的是大量正常项。

优化后的核心阅读顺序应为：

```text
整体是否可信
→ 有多少项需要关注
→ 按风险查看具体论断
→ 展开一条查看判断原因与修改建议
→ 按需核对最小原文证据
```

- 折叠式论断条目；
- 展开后展示完整详情；
- UI 展示层证据文本清理；
- 多证据紧凑展示；
- 筛选计数和空状态；
- 现有分析、导出、返回和历史来源信息不回归；
- 桌面端和窄屏视觉验证；
- 聚焦测试与完整回归。

### 暂不完成

- 重新检索或重新判断单条论断；

## 四、目标布局

### 4.1 顶部结果摘要

将当前大等级卡片和六个等宽 Metric 合并成紧凑摘要区域：

```text
← 返回论文讲解

审计结果   [需复核]
74 分      覆盖率 86%   证据发现率 91%   严重 0   高风险 2   待复核 4
```

要求：

- 总高度尽量控制在约 84–110px；
- 可信等级是主要视觉信息，总分次之；
- 严重和高风险为 0 时使用中性样式，不制造警报感；
- 有严重或高风险时使用克制的红色/橙色强调；
- `total_score is None` 显示“未评分”；
- 保留现有浅灰白背景和绿色主色，不引入新的高饱和配色系统。

### 4.2 页签

保留三项：

```text
逐条审计 | 六维分析 | 报告导出
```

去掉不必要的 Emoji 和过长文案，减少视觉噪音。不能改变三个区域已有功能。

### 4.3 筛选区

第一层快速筛选使用分段选择：

```text
[需关注 6] [全部 30] [冲突 1] [未找到证据 3] [证据不足 2]
```

规则：

- “需关注”包含除 `SUPPORTED + Severity.NONE` 之外的论断；
- 如果存在需关注项，进入结果页默认选择“需关注”；否则默认“全部”；
- 每个选项显示真实数量；
- 选择快速筛选后，再叠加高级筛选和关键词搜索。

第二层保留：

- 分类；
- 风险等级；
- 关键词；
- 排序：风险优先 / 报告顺序。

桌面端尽量保持一行；空间不足时自然换行。不要使用固定像素宽度造成溢出。

### 4.4 论断列表

所有论断默认呈现为紧凑折叠行：

```text
▶ C014 · 实验结果
  SAM 在 23 个数据集中的多数指标优于 RITM……
  [冲突] [高风险] [2 条证据]
```

要求：

- 折叠状态最多显示两行论断摘要；
- 标签靠近论断信息，不再漂到页面最右侧；
- 每条折叠行高度建议控制在约 64–88px；
- 论断间使用细分隔线或轻边框，不重复嵌套大卡片；
- 默认全部折叠，避免进入页面后生成数十个高卡片；
- 展开/折叠必须有稳定的 Streamlit key；
- 筛选或排序后不能打开错误的论断。

展开内容结构：

```text
完整论断
……

判断说明
……

修改建议（仅有内容时显示）
……

原文证据 · 2
证据 1   P12 · p12_b33
原文……
```

### 4.5 证据展示

增加纯展示辅助函数，例如：

```python
def normalize_evidence_display(text: str) -> str:
    return " ".join(text.split())
```

约束：

- 只用于 HTML/UI 文本；
- 不修改 `EvidenceCandidate.text`；
- 不修改 `AuditRun`、JSON、Markdown 导出；
- 合并换行、Tab 和连续空格；
- 每条证据显示“证据 N、页码、Chunk ID”；
- 证据正文使用正常段落宽度和 `line-height: 1.6`；
- 超长内容允许自然换行，不能水平滚动；
- 没有命中证据时显示“当前没有已验证的原文证据”，不能保留空白证据框。

## 五、实现建议

优先修改：

```text
src/paperaudit/ui/audit_results.py
src/paperaudit/ui/components.py
src/paperaudit/ui/styles.py
```

必要时新增一个小型纯函数模块或在 `audit_results.py` 中放置筛选与排序函数，但不要创建复杂前端框架。

建议拆分纯函数：

```python
def is_attention_required(audit: ClaimAudit) -> bool: ...
def filter_audits(...args...) -> list[ClaimAudit]: ...
def sort_audits(...args...) -> list[ClaimAudit]: ...
def normalize_evidence_display(text: str) -> str: ...
def audit_counts(audits: Sequence[ClaimAudit]) -> dict[str, int]: ...
```

纯函数便于测试，Streamlit 渲染函数只负责组件和状态。

### 5.1 折叠组件

第一版优先使用 `st.expander`，不要引入自定义 JavaScript。Expander 标题中使用简短纯文本：

```text
C014 · 实验结果 · 冲突 · 高风险 · 2 条证据
```

标题下方或展开内容顶部再以现有 Badge 样式显示判定和风险。不要把未经转义的模型文本放入 HTML。

### 5.2 默认筛选状态

建议状态键：

```text
audit_quick_filter
audit_category_filter
audit_severity_filter
audit_search_query
audit_sort_mode
```

打开另一条历史审计时，应根据 `AuditRun` 建立独立或重置后的合理默认状态，不能沿用与新结果不兼容的分类值。

### 5.3 性能

- 30–100 条论断时页面仍应可操作；
- 不为每条折叠论断创建额外模型调用；
- 筛选和排序仅处理内存列表；
- 不重复序列化完整 `AuditRun`；
- 下载内容可以按当前方式生成；
- 不使用自动定时刷新审计结果页。

## 六、样式要求

新增样式建议以 `.pa-audit-*` 为命名空间：

- `.pa-audit-summary`
- `.pa-audit-summary-grade`
- `.pa-audit-summary-metrics`
- `.pa-audit-count`
- `.pa-audit-detail-section`
- `.pa-audit-evidence-list`
- `.pa-audit-evidence-item`
- `.pa-audit-empty`

要求：

- 内容最大宽度继续沿用应用主工作区，不额外缩成窄列；
- 证据正文 `white-space: normal`，不使用当前的 `pre-wrap`；
- 论断和解释建议限制阅读宽度约 `85–100ch`，但证据容器本身占满可用宽度；
- 使用 1px 浅色边框和 6–10px 圆角；
- 减少阴影；
- 正文不小于约 13px；
- 桌面端不出现大面积无信息空白；
- 深色模式保持可读，但不为此重做主题系统。

## 七、错误与空状态

必须覆盖：

- 审计结果没有任何论断；
- 快速筛选无结果；
- 高级筛选组合无结果；
- 论断没有候选证据；
- 判断引用了不存在的 evidence ID；
- `total_score=None`；
- 修改建议为空；
- 证据文本为空或只有空白；
- 论断文本特别长；
- 30 条以上论断；
- 历史审计切换后旧筛选值不适用。

空状态示例：

```text
当前筛选条件下没有论断
[清除筛选]
```

## 八、测试要求

新增聚焦测试，至少覆盖：

1. `normalize_evidence_display()` 能折叠 PDF 硬换行和连续空格；
2. 不修改原始 `EvidenceCandidate.text`；
3. “需关注”正确排除 `SUPPORTED + NONE`；
4. 冲突、未找到证据和证据不足计数正确；
5. 分类、风险和关键词筛选可以叠加；
6. 风险优先排序为严重、高风险、中风险、低风险、无风险；
7. 报告顺序保持输入顺序；
8. 引用不存在的 evidence ID 时不报错；
9. 没有证据或建议时不生成空详情块；
10. `total_score=None` 能正确显示。

完成后执行：

```powershell
uv run pytest -q
uv run python -m compileall -q app.py src tests
```

## 九、浏览器视觉验收

使用现有或演示审计结果验证：

### 桌面端

- 1920×1080：摘要、页签、快速筛选在首屏清晰可见；
- 1440×900：筛选区不拥挤，论断标题不与标签重叠；
- 1280×800：高级筛选可自然换行，无横向滚动；
- 30 条论断默认不全部展开；
- 展开一条后证据正文充分利用宽度；
- PDF 抽取换行不再形成左侧窄文字柱；
- 支持项和问题项视觉层级明确；
- 下载、返回、历史审计展示正常。

### 窄屏

- 390px 宽度下摘要指标自动换行；
- 快速筛选与高级筛选不溢出；
- Expander 标题允许换行且仍可点击；
- 证据正文不产生横向滚动。

视觉验证后必须恢复浏览器视口，并停止临时预览服务；用户原本运行的正式服务不应被误停。

## 十、最终验收标准

以下条件全部满足才算完成：

- 首屏能够快速判断整体可信度和问题数量；
- 默认优先显示需要关注的论断；
- 30 条论断不再全部展开成超长卡片；
- 用户可以按状态、风险、分类和关键词快速定位；
- 每条论断折叠状态仍能看懂主要内容和风险；
- 展开后判断说明、建议和证据结构清楚；
- PDF 抽取硬换行只在 UI 展示层被清理；
- 多条证据不会制造大面积空白；
- 无证据、无建议和无筛选结果都有合理空状态；
- 六维分析、风险统计、导出、返回和历史来源没有回归；
- 桌面端与窄屏没有横向溢出；
- 全部测试和编译检查通过；
- README 如需描述 UI 行为，只写已经实现的事实；
- 未修改审计算法、评分和存储格式；
- 没有残留临时文件或临时服务。

## 十一、允许自主决策的默认项

执行 `/goal` 时无需因以下事项暂停：

- 默认快速筛选选择“需关注”；没有需关注项时选择“全部”；
- 默认排序为风险优先；
- Expander 默认全部折叠；
- 证据展示文本通过 `" ".join(text.split())` 清理；
- 快速筛选使用 Streamlit segmented control；
- 高级筛选继续使用 selectbox/text input；
- 复用现有标签中文映射和 Badge 配色；
- 使用 Fake/Demo AuditRun 做确定性测试与视觉预览；
- 不调用真实 Hy3 API 完成 UI 验证。

## 十二、停止条件

达到验收标准后停止，不继续主动增加：

- 单条重新审计；
- 审计差异比较；
- 报告自动修订；
- PDF 双栏结果工作台；
- 笔记、高亮和评论；
- 新图表库；
- 审计记录管理系统；
- 其他页面的视觉重构。

这些功能只在用户后续明确要求时再评估。
