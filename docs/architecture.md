# 模块边界与项目状态

本次拆分保留 `AuditService(settings, client)` 及既有方法签名；模型提示词、评分规则、证据匹配算法和持久化格式不变。

## 服务层

- `service.py`：讲解、问答和报告审计的编排入口；审稿方法委托给 `PeerReviewService`，旧辅助函数导入路径继续兼容。
- `peer_review_service.py`：模拟评审生成、相关工作比较和作者回复评估，复用调用方的模型客户端。
- `peer_review_rules.py`：权重、确定性评分、一致性检查和版本差异等纯逻辑。存储层直接依赖这个模块，避免为重算评分加载完整服务。
- `evidence.py`：引文逐字校验、章节/段落定位、矩形范围与相邻上下文恢复，由讲解、问答、审稿及审计界面共享。

## 页面层

- `app.py`：应用启动、任务管理器、项目结果路由及任务回调。
- `ui/sidebar.py`：项目列表、搜索、切换、删除入口及模型配置。
- `ui/storage_setup.py`：首次设置保存目录。
- `ui/upload.py`：上传与生成设置，返回明确的 `UploadSubmission`。
- `ui/upload_actions.py`：提交后的解析、保存、同步讲解或后台任务提交。
- `ui/upload_preview.py`：上传论文的 PDF 预览与阅读控件。
- `ui/rubric_controls.py`、`ui/constants.py`：评审标准控件和显示常量。

## 会话状态

`ui/project_session.py` 的 `ProjectSession` 负责项目恢复、切换、清理和新讲解初始化。侧栏、URL 路由、上传流程及讲解页的“更换论文并返回”使用同一套规则。

切换先保存当前对话，再完整读取目标项目，读取失败时保留当前项目内容。成功后清理旧报告、问答草稿、代码选择、PDF 定位、修改稿预览、人工复核控件及动态审计筛选状态。API 配置、检索参数和评审权重作为会话偏好保留。

提交上传时已经渲染的表单控件保留至后续导航，以遵守 Streamlit 的控件状态限制；它们不会通过新建/切换项目带入另一篇论文。新增项目相关控件应使用已登记的项目状态前缀，或加入显式清理键集合。

## 验证边界

新增测试覆盖真实入口的首次设置、三种空上传模式、侧栏与 URL 切换，以及使用真实本地存储的三种上传处理流程。模型调用使用替身，不请求真实 API。AppTest 无法运行浏览器侧 PDF 选择组件，因此导航测试仅替换该组件的挂载调用，保留 PDF 处理和工具栏路径；浏览器选区交互不在这些测试的覆盖范围内。
