# 候选证据漏看复审（2026-09-24）

本轮针对“候选片段里已有表格或数字，但初审仍返回无支持、待核验或片面结论”的问题，建立了两篇新论文的开发集：ShuffleNet（1707.01083v1）和 SqueezeNet（1602.07360v1）。两篇论文没有出现在现有审计样本或最终保留集清单中；原 PDF、SHA-256、候选和参考证据在协议中冻结。

样本包含 14 个生产检索案例：8 个完整支持、4 个数字/配置错误、2 个范围过度概括；另有 2 个主动删除关键表格的对照和 4 个补齐完整证据的依赖探针。表格和关键行已渲染检查。完整证据探针不计入自然案例指标。

## 基线

基线对每个案例执行一次 `judge_claims`，再走现有引用完整性校验。自然案例结果：

| 指标 | 结果 |
| --- | ---: |
| 标签与参考一致 | 7/14 |
| 支持参考案例 | 8 |
| 支持漏判 | 6 |
| 误报为支持 | 0 |
| 待核验 | 7 |
| API 请求 / token | 29 / 97,969 |

主要漏判来自候选只包含表格说明、表头或相邻正文，模型没有把候选池中的结构化片段视为可以继续核对的证据。主动删除表格的对照仍正确保持待核验或无支持。

## 复审方案

最终判断不是支持时，如果论断含数字，且候选中有表格标记或多数字行，触发一次 `review_candidate_gap`。提示要求模型检查全部候选的表头、配置行、单位、数值和比较对象。

只有复审明确返回完整 `SUPPORTED`、引用编号合法时才替换原判断；复审返回部分支持、矛盾或无支持时保留原判断。这样避免统一错误类型校准把“证据缺口”升级成 `CONTRADICTED`。恢复为支持后仍经过逐字引用完整性校验和一次有界引文修复。

## 对照结果

完整候选复审运行覆盖了 20 个冻结案例，10 次候选复审请求，27,479 tokens。候选运行中途另做了一次重新运行；因两次 API 连接失败，系统停止派发，失败行不计入准确率，也不自动重试。

按最终“只接受明确完整支持”的规则，对完整候选运行保存的复审结果重新计算：

| 指标 | 基线 | 复审后 |
| --- | ---: | ---: |
| 标签与参考一致 | 7/14 | 11/14 |
| 支持漏判 | 6 | 2 |
| 误报为支持 | 0 | 0 |
| 复审次数 | 0 | 6 |

复审减少了四个支持漏判，没有增加误报。剩余两例仍因首次候选没有包含对应的具体表格行而无法恢复；复审不能从全文重新检索，也不会凭空添加候选。一个初版复审曾把部分支持升级为矛盾，已由“只有完整支持才能替换”规则修正，并有回归测试覆盖。

这组数据是开发诊断，不是整体准确率：参考证据由人工核对 PDF，但没有独立盲注释；样本很小，且补齐证据探针与自然案例存在依赖。最终保留集未参与取样、调参或复审。

## 实现与检查

- `src/paperaudit/evidence_gap.py`：触发条件与有界复审。
- `src/paperaudit/service.py`：将候选复审接在初审之后、引用完整性复核之前。
- `src/paperaudit/hy3_client.py`：结构化复审提示。
- `eval/evidence_gap_experiment.py`：冻结候选、运行、断点保护和指标统计。
- `eval/evidence_gap_review_20260924.json`：逐案例前后结果、复审响应和源文件散列。

全量测试：**307 passed**。最终保留集隔离检查仍通过。

运行时只在内存中读取 API key；协议和请求日志不保存密钥。每个请求开始前写入脱敏检查点，连接失败后停止后续派发，避免不知情地重复计费。
