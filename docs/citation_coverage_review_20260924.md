# 支持结论的引用完整性复核（2026-09-24）

上一轮首次检索已找到 MobileNet Table 8，但裁决只选正文段 `p6_b6`。正文支持 MobileNet 相比 VGG16 的约 27 倍计算量差异，单独不能确认 224 配置。此次增加最终引用复核，避免把“候选里有证据”当成“最终引用已覆盖”。

## 实现

所有最终 `SUPPORTED` 结论（包括高风险无支持补查后恢复的结论）均经过一次逐项复核。模型检查论断的主体、配置、比较对象、指标、条件、数值、单位和结论强度，为每项选择候选编号及连续原文引文；允许解释同义表达、跨片段关联和合理计算。

本地校验只接受正确 claim ID、合法候选编号、非空逐项依据，以及原片段中的连续引文。仅规范化空白，不容许拼接、重排表头、改写数字或从其他片段借用文字。最终编号必须与逐项引用中出现的编号完全一致。所有证据由模型明确选择，程序不把整个候选池补入引用。

模型声称完整但引文转录/编号校验失败时，允许一次修复。明确缺少必要依据、claim ID 错误或结构无法解析时不追加这次修复。修复后仍失败则 `ABSTAIN`，清空最终引用及事实错误类型，不因引用缺口给报告定性为编造。原始判断、复核记录和修复前记录均保留在审计 JSON；旧记录没有这些字段仍可载入。报告伪造页码的本地检查在该步骤后执行，仍能显示高风险页码错误。

每条支持结论通常多一次 API 调用；局部修复最多再一次。既有 JSON 格式修复仍可能额外调用，SDK 的传输重试沿用生产配置。引用不完整不会触发无限循环。

## 冻结样本验证

使用上一轮 `cited-retrieval-20260924` 已冻结的 15 条候选和裁决：13 条支持、2 条无支持。直接复用旧判断，单独衡量引用复核；不重新抽取、检索、投票或生成初始标签。另增加一个对照：对相同 MobileNet 论断只提供原来选中的正文片段，不提供表格。

使用用户指定的 `gpt-6-luna`，temperature 0.2、top_p 1、请求上限 6,000 completion tokens、120 秒超时，SDK 重试关闭。密钥仅隐藏输入，不保存。协议冻结输入、代码及运行配置散列；请求开始前写入无密钥日志，避免中断后自动重复计费。

冻结实验共 17 次请求、67,756 tokens，无请求失败。此前有两次探索调用，不包含在该 token 数中。探索阶段再次观察到初审会把完整候选中的 MobileNet 表格漏看并判为部分支持；当前改动只处理最终支持结论，不能解决这类初审假阴性。

## MobileNet 结果

原始引用：`C023_e1 → p6_b6`，只引用正文。

最终引用：`C023_e8 → p6_b9`，由模型重新选择 Table 8，原文完整包含：

- `1.0 MobileNet-224`，计算量 `569` Million Mult-Adds；
- `VGG 16`，计算量 `15300` Million Mult-Adds；
- 表头和指标单位。

模型明确计算 `15300 / 569 ≈ 26.89`，与正文约 27 倍一致。最终引用选择了表格本身，不是程序自动追加候选。完整表头和行引文通过本地连续原文检查。

在只提供正文的对照中，模型明确指出未证实 MobileNet-224 配置，返回 `complete=false`；系统将原支持标签降为待核验，未尝试补造配置或将其标为事实编造。

## 边界

15 条是诊断样本，参考也经过模型辅助，15/15 不代表整体准确率。局部修复在同一批失败样本上开发和验证，仍需要独立样本检验泛化。程序能确定引文存在，不能确定模型是否漏掉某个语义条件；没有把本地逐字校验声称为完整性证明。部分支持、矛盾、无支持的引用完整性不在本轮范围，初审遗漏表格导致的假阴性也尚未解决。额外调用会增加审计时间和费用。
