# 证据检索改进结果

## 改动

修改 [src/paperaudit/retrieval.py](../src/paperaudit/retrieval.py)：

1. 对 PDF 断词、连字和乘号做统一规范化，例如 `pre-\ntraining` 与 `pretraining` 归一；
2. FTS5 只索引规范化文本，同时保留原始文本用于展示；
3. 第一阶段扩大候选池到至少 500 条，再做轻量混合重排；
4. 重排同时考虑查询词覆盖率、数字命中率、BM25 相对分数和完整短语命中；
5. 对作者归属查询补入论文首页摘要前的作者块，并提高前置材料权重；
6. 对数字/指标查询增加上下文锚定、通用词形归一，以及“数字 + 指标”邻近匹配，降低被无关数字表格吸走的概率。

## 摘要证据排序与自动裁决重试

为解决跨论文共性的首页摘要漏召回问题，检索器现在通用识别第 1 页摘要块，将其实质性段落加入候选并给予有限排序加成；未使用论文 ID、样本 ID 或专属术语。开发集和 4 篇留出集的离线 Top-5 金标召回率均达到 100%。

同时增加一次自动证据引用重试：当模型未返回结构化判断、返回 `ABSTAIN`，或引用不存在的候选证据编号时，系统自动调用单条裁决；重试仍无效才保留 `ABSTAIN`，不再提示用户进行人工复核。相关逻辑已接入正式审核服务和评测脚本。

最新留出集真实评测（32 条）结果：Top-5 召回率 100%，标签准确率 90.62%，标签宏平均 F1 0.8898，错误类型准确率 82.61%，风险等级准确率 90.62%，`ABSTAIN` 比例 0%。标签和风险指标达到预设阈值；错误类型在不同 API 运行间存在随机波动（此前为 86.96%），因此不再针对单个样本继续调参。完整测试为 112 passed。

## 有限多数裁决

对已被边界规则标记的样本，系统保留首次判定并追加一次单条裁决；若两次的标签/错误类型不一致，再追加第 3 次并采用多数结果。证据编号重试仍优先接受新的有效引用，避免无效编号与旧结果打平。普通明确样本不重复调用 API。

留出集真实评测（`results_holdout_actual_v5`）结果与上一轮一致：标签准确率 90.62%，宏平均 F1 0.8898，错误类型准确率 82.61%，风险等级准确率 90.62%，`ABSTAIN` 0%，Top-5 召回率 100%。这表明当前主要波动来自错误类型边界与金标定义差异，而不是单纯重复调用不足；继续增加调用次数没有可观测收益，后续冻结该机制。

## 第二批跨论文边界校准

新增 3 篇未参与前序规则调优的论文：Adam（arXiv:1412.6980 v9）、Dropout（arXiv:1207.0580 v1）和 Neural Machine Translation by Jointly Learning to Align and Translate（arXiv:1409.0473 v7）。三份 PDF 均完成 SHA-256、页数和证据 chunk 校验，共 24 条原子论断，覆盖 `missing_condition`、`overgeneralization`、`contradiction` 以及外部幻觉、数字错误等对照样本。

本批样本采用统一边界：

- `missing_condition`：核心事实在明确设置下成立，但报告遗漏了必要设置条件；
- `overgeneralization`：证据只覆盖有限任务、数据集或设置，报告扩展为“所有/任何/始终”等全称结论；
- `contradiction`：证据直接否定同一主体和设置下的事实、数值或归属；若证据只描述相关方法而未讨论报告新增的应用/数据集/机制，则标为 `external_hallucination`。

初始标注中有 3 条同时包含条件遗漏和全称扩张，容易造成边界混淆；按上述优先级重新标注为 `overgeneralization`，未修改模型规则以迎合单个结果。

第二批真实 API 评测（24 条，`results_extended_actual_v4`）：Top-5 召回率 95.83%，标签准确率 100%，错误类型准确率 100%，风险等级准确率 100%，`ABSTAIN` 0%。同时修复了批量响应格式异常的通用降级：批量 JSON 失败时自动逐条裁决，单条仍失败才保留 `ABSTAIN`，不会中止整轮评测。

## 正文证据集验证

从上述 3 篇跨领域论文的正文方法、实验设置和指标段落新增 24 条样本，全部完成证据映射。正文集离线 Top-5 召回率为 87.5%，真实 API 两次运行分别为：标签准确率 70.83%/83.33%，错误类型准确率 60.00%/76.47%，风险等级准确率 79.17%/91.67%，`ABSTAIN` 均为 0%。

正文集暴露的主要问题是正文资源配置块（GPU、训练时长）进入 Top-5 不稳定，以及“未讨论的外部应用”与“直接否定”在模型解释中仍有边界波动；这与摘要集的高指标不同，说明当前系统不能只用摘要集结果代表整体审核能力。后续优化应优先做通用资源/表格证据召回和边界样本扩充，并继续保留正文集作为独立验收集。

## 正文资源检索优化

新增通用资源配置锚点，对 GPU/CPU、V100、显存、训练时长、批大小和训练/推理等词进行词形归一和上下文加权，并加入对应回归测试。开发集和原留出集 Top-5 召回率保持 100%，正文集保持 87.5%，没有产生回归；正文集的 LARGE 模型 GPU 配置仍在第 5 名之外，说明下一步需要做“模型配置实体 + 资源数值”的联合匹配，而不是继续提高单一资源词权重。

## 配置实体—资源数值联合匹配

检索器进一步要求查询中的具体配置实体（如 BASE、LARGE、variant）与 GPU/V100、显存、时长或 batch 等具体资源词在同一候选段落内邻近出现，才给予联合加分；泛化的 `model` 或 `training` 单词不会单独触发该加分。开发集和原留出集 Top-5 召回率仍为 100%，正文集从 87.5% 提升至 91.67%，扩展跨领域集保持 87.5%。

真实正文评测（`results_body_actual_v4`）结果：标签准确率 91.67%，宏平均 F1 0.8601，错误类型准确率 88.24%，风险等级准确率 95.83%，`ABSTAIN` 0%，Top-5 召回率 91.67%。资源配置联合匹配带来正文证据发现率提升，同时没有破坏已有开发集和留出集基线；当前仍有两个非资源类正文概念证据漏召回，后续应单独建设概念/应用实体对照样本，不再扩大资源词权重。

## 规则冻结前整理
