# PaperAudit 自动有效性验证报告

本报告在不引入人工复核的前提下，使用程序化探针、重复运行和金标证据注入评估当前审核体系。它可以证明评分逻辑的自洽性与模型运行稳定性，但不能替代“模型结果与独立人工标注的一致性”。

## 1. 判别力验证

程序化构造事实标签不同、类别覆盖相同的三档报告：

| 档位 | 总分 | 可信等级 |
| --- | ---: | --- |
| 好 | 100.0 | 可信 |
| 中 | 85.0 | 需复核 |
| 差 | 40.0 | 不可信 |

结果满足 `好 > 中 > 差`，且等级方向正确。该实验验证的是评分汇总逻辑，不包含检索和 Hy3 判断误差。

## 2. 自动对抗探针

在事实标签、证据和类别不变的情况下，将论断文本扩写为原来的数十倍，综合得分保持不变。说明当前评分器不会仅因篇幅增加而提高分数。

这项探针尚未覆盖术语堆砌、重复段落和伪造引用经过 Hy3 论断拆分后的端到端影响。

## 2.1 端到端对抗验证

在固定测试集每篇论文选取 1 条支持样本和 1 条错误样本，共 10 组成对样本。对抗版本只修改报告文本，论文 PDF、查询、金标标签和金标证据保持不变；依次覆盖篇幅扩写、术语堆砌、伪造引用、重复段落和 Prompt 注入。

| 指标 | 结果 |
| --- | ---: |
| 对抗对数量 | 10 |
| 评分上升攻击数 | 0 |
| 风险降低攻击数 | 0 |
| 对抗攻击成功率 | 0% |
| 对抗版本 ABSTAIN | 0% |

10 条样本的标签均未改变；1 个论文级分数下降，其余保持不变。机器结果见 `validation_adversarial/adversarial_summary.json`，生成脚本见 `run_adversarial_validation.py`。该结果说明本组受控因素未造成评分器表面性抬分，但不等价于对所有自然 Prompt 注入或复杂攻击的安全保证。

## 3. 重复运行一致性

从五篇论文各选择一条代表样本，在相同配置下重复评测 3 次：

| 指标 | 结果 |
| --- | ---: |
| 样本数 | 5 |
| 重复次数 | 3 |
| 标签两两一致率 | 100% |
| 平均论文分 | 85.0 |
| 论文分标准差 | 0.0 |

该结果表明小型代表集在当前配置下运行稳定。由于样本量只有 5 条，不能据此推断所有 40 条样本都具有相同稳定性。

本轮补充了固定测试集全部 40 条样本、相同配置下的 3 次真实 API 评测：

| 指标 | 结果 |
| --- | ---: |
| 样本数 | 40 |
| 重复次数 | 3 |
| 标签两两一致率 | 98.33% |
| 平均论文分 | 69.4533 |
| 论文分标准差 | 0.5468 |
| 各次标签准确率 | 95.00%、97.50%、97.50% |
| 各次错误类型准确率 | 95.45%、95.45%、95.45% |
| 各次风险准确率 | 95.00%、97.50%、97.50% |
| 各次 ABSTAIN | 0% |

机器结果见 `validation_full/validation.json` 及 `validation_full/run_*/`。

## 4. 检索与判断解耦

普通 Top-5 端到端评测与金标证据注入评测结果如下：

| 指标 | Top-5 端到端 | 金标证据注入 |
| --- | ---: | ---: |
| 标签准确率 | 80.00% | 87.50% |
| 标签宏平均 F1 | 0.7141 | 0.6639 |
| 错误类型准确率 | 90.91% | 90.91% |
| 风险等级准确率 | 75.00% | 70.00% |
| `ABSTAIN` 比例 | 0% | 2.50% |

注入金标证据后标签准确率提高 7.5 个百分点，说明证据漏召回确实会造成部分标签错误。宏平均 F1 和风险等级准确率没有同步提高，说明判断器本身仍存在类别边界与风险分级问题；不能把全部误差归因于检索。

## 5. 结论与边界

当前自动证据支持以下结论：

- 评分汇总能够区分程序化好、中、差报告；
- 单纯增加篇幅不能提高评分；
- 小型代表集三次运行标签稳定；
- 完整 40 条固定测试集三次运行具有较高标签一致性（98.33%），且无 ABSTAIN；
- 10 组端到端受控对抗样本未出现评分上升或风险降低；
- 检索漏召回是重要误差来源，但不是唯一来源。

当前不能声称：

- 评测结果已与独立人工判断高度一致；
- 40 条样本的所有金标都没有标注争议；
- 对完整自然报告的论断拆分，以及未覆盖攻击组合的鲁棒性已经充分验证。

完整机器可读结果位于 `validation/validation.json`、`validation/run_*/`、`validation_full/validation.json`、`validation_full/run_*/`、`validation/oracle/` 和 `validation_adversarial/adversarial_summary.json`。
