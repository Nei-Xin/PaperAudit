# 矛盾引用门禁与表格定位回归（2026-09-24）

## 改动目的

此前三篇新论文测试发现，SENet 的 SE04、SE05 虽被正确标为 CONTRADICTED，
但本条候选只有表题，没有证明冲突的数据行。纠正值正确不能代替引用证据链。
另有 RX01、LN03 因表题位于数据下方、表头分块而漏召回，引用门禁将其保留为弃权。

本轮新增和修复：

- SUPPORTED 和 CONTRADICTED 都经过引用完整性门禁；复核记录明确标明其目标标签。
  旧支持复核记录仍能加载，但不会用于放行矛盾结论。
- 矛盾复核要求同一主体、模型配置、任务、指标和评估条件下的明确冲突，逐项提供
  原文引文；不能借用同批其他论断的候选或旧判定中的纠正数值。
- 缺少原文、指标/条件不完整或引文无法本地验证时转为 ABSTAIN，清除未经证实的
  错误类型、风险等级及具体纠正建议，保留原判定和复核记录供追溯。
- 最多进行一次引文格式修复；语义缺口及目标标签错误不通过格式重试绕过门禁。
- 表格检索利用 PDF 坐标区分左右栏，从表题上方或下方寻找最近的连续结构区域。
  每个方向最多扫描十二块，遇到正文、另一表题、页边界或过大垂直距离停止。
  报告明确指出的表号在已检索到的表题中优先；缩写组成的列头也可识别。
- 保留全局前五个候选，引用页最多增加三块，整体预算仍为十块及18,000字符。
  不拼接、重写或截断原文。没有几何信息的旧索引保留按块顺序的有界回退。
- 界面和 Markdown 的“复核通过”使用实际引文校验结果，不仅看模型的 complete。
  结构化复核失败时也显示未通过。

## 验证方法

此轮重用 `unseen-e2e-20260924` 的已见论文、报告及冻结参考标签，是开发回归，
不是新的独立泛化测试。生产代码、输入及控制组在真实请求前冻结，没有根据输出
改写预期或重跑选优。API key 仅使用隐藏输入，不写入文件。

1. **相同论断离线对照**：复用上一轮抽取的十八条论断，只改变检索；有参考原文的
   十五条中，完整参考块覆盖从 8/15 提升到 15/15。该指标并不等同于语义充分性。
2. **历史开发集回归**：九个非最终验收集均通过既有门槛，cited 相比 plain 新增
   七例命中，没有丢失 plain 已命中案例。ShuffleNet/SqueezeNet 自然案例完整覆盖
   保持10/14。最终留出集只做论文隔离检查，不使用其标签或模型输出调整实现。
3. **完整生产链路**：重新执行三份报告的自动抽取、检索、判定及复核，记录结果和用量。
4. **冻结候选控制组**：重用上次六条 CONTRADICTED 的原始候选和原判定，只调用新门禁。
   预期四条已有充分原文的判定保留，两条仅有表题的 SE04、SE05 转为 ABSTAIN。
   此控制组用于区分“补全检索”与“无证据时不指控”的作用。

自动测试覆盖缺行、错目标标签、错论断编号、伪造引文、跨来源编号、缺少复核结果、
一次修复边界、生产服务接入、持久化字段、UI/导出状态、表题在下方及左右栏交错。
本轮初始回归时全量338项测试通过；后续门禁加固后离线测试增至341项，最终留出集隔离检查通过。

## 后续加固（当前提交）

针对 LN04 暴露的附加纠正数值缺少引文问题，`CitationReview` 新增
`suggestion_verified` 和 `suggestion_missing_aspects`。新生成的 CONTRADICTED
复核若带有纠正建议，必须显式确认建议中的每个具体数值、配置和条件都由引文覆盖；
否则最终结论转为 ABSTAIN，并清除建议。旧的 SUPPORTED 复核记录仍可按兼容规则读取，
但新矛盾复核不会默认放行缺少该字段的结果。界面和 Markdown 会显示纠正建议的复核状态。

已经明确为 CONTRADICTED 的判断也不再重复执行“候选缺口复查”；它们直接进入矛盾引文
门禁，避免一次重复模型请求。缺少支持、弃权和部分支持判断仍保留候选缺口复查。

真实 API 结果文件记录的是加固前的开发回归，因此其中的18/18和6/6不能作为新字段
在真实服务上的验证。当前变更已由341项离线测试覆盖；下一次真实回归应重新冻结输入，
重点检查纠正建议覆盖和请求数变化。

## 真实 API 结果

使用 `gpt-6-luna` 完成三份报告，十八条原句全部抽取，标签一致数由16/18升至18/18。
九条 SUPPORTED 和六条 CONTRADICTED 均通过本地引文及编号校验，另外三条为
NO_SUPPORT_FOUND，没有错误放行为支持。RX01、LN03 均恢复为支持；SE04、SE05
现在引用实际数值行和表题，能分别证明23.19与23.40、24.80与23.29的冲突。
这是已见案例的开发回归结果，不能据此估计新论文上的准确率。

### 人工复核发现的剩余缺口

LN04的主要冲突有表头、†模型行和训练条件支持：对应MSE为0.270，反驳报告中的0.277。
但继承的纠正建议额外写出“非†模型训练100万次、MSE为0.277”，最终引用复核未引用
这个对照行。模型虽被提示验证建议中的数值，仍漏掉了该附加断言；本地规则只验证
所给引文是否存在，不能自动发现未列出的语义方面。因此不将15/15本地引文通过
表述为“全部纠正文本已被证明”。下一轮应独立验证纠正建议，或仅从已核实引文生成建议，
并冻结包含附加比较断言的新回归案例。本轮保留原始结果，不因该发现重跑选优。

## 限制

引文的存在、来源和集合一致性由本地规则校验，但“是否构成同一条件下的冲突”
仍由模型判断，需要继续在新的论文和真实报告上验证。表格定位是有界启发式，
不保证覆盖跨页表格、复杂合并单元格或所有多栏排版。新增矛盾复核增加请求和延迟，
不能将这一轮与上一轮的耗时差完全归因于代码；服务端时延与抽取输出也可能变化。
