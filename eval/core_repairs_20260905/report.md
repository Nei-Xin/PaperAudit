# 引用、范围漏抽与高风险误报修复验证

本次完成指定的三项修复，第三项限于一次补查和证据不足时转人工复核。没有调整评分权重或更换检索架构。

## 实现

1. 分句保留句末括号引用，按本地原句补回 `provided_evidence`；越界页码由程序确定性标记为 `fabricated_evidence`，不依赖模型记住校验。
2. 抽取时携带报告章节，明确“在哪些数据/任务上进行评估”属于请求的 `results` 范围。若模型把这类内容跳过，触发一次现有批次重试；不把预处理、数据划分等所有设置一并纳入结果范围。
3. 高风险 `NO_SUPPORT_FOUND` 最多进行一次补查：优先引用页，至多增加五个片段并保留原证据编号，再要求模型判断材料是否足够。材料不足、结构无效或引用无效时转为 `ABSTAIN`，保留人工复核；材料足够的明确错误仍可保留高风险。此流程不能保证所有正确事实自动判为支持。

## 验证

自动化测试：**197 项通过**。第一次全量运行有一项未修改的评审任务测试因 Windows 临时文件原子替换遇到访问拒绝而失败；单独重跑和随后的全量运行均通过，没有修改该模块。

真实 API：使用上一轮已知失败的 R002、R005、R018 各运行一次，模型及配置保存在 [config.json](config.json)。这是开发回归，不是新的独立留出集或三次稳定性验证。

引用与范围修复在三个报告上通过；第三项实现了保守复核，但不支持“所有风险自动检出且没有误报”的结论。按本次要求到此停止，不继续为单个样例扩展检索或调参。
