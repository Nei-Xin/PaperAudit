三篇此前未进入项目历史实验清单的论文均完成真实 API 审计。
18 条论断完整抽取，16/18 与冻结参考标签一致，未出现错误的“支持”结果。
但有两条正确论断因缺少表头而被保留为“无法判断”，另有两条“矛盾”判定
虽然标签正确，引用却不足以证明具体数值冲突。后者是本轮最需要优先修复的问题。

## 论文、样本与执行边界

| Layer Normalization | https://arxiv.org/pdf/1607.06450v1 | 14 | 6 | 5/6 | 130.4 秒 |

- 从 arXiv 下载原始 PDF，固定版本与 SHA-256；共解析 35 页、1,211 个块。
- 每篇构造一份中文报告，包含三条正确论断、两条数字/配置错误、一条无支持结果。
  参考依据在运行前经过 PDF 页面可视核对，样本和预期标签均先冻结。
- 使用 `045b672` 的生产实现，调用 `AuditService.audit()`，完整经过自动抽取、
  检索、初审、必要的二次判定、无支持补查、候选复审与引用复核。
- 使用用户指定的 `gpt-6-luna` 和 API 地址；请求返回的模型名一致。报告级并发为 2。
  没有绕过引用门禁、直接注入原子论断/金标，或根据结果重跑选优。
- 最终留出集未参与结果分析或实现选择；论文隔离检查通过。
- 三个报告的真实审计结果均通过 `ProjectStore` 保存、加载后的完整对象一致性检查，
  并生成 Markdown 审计导出。此次没有浏览器 UI 人工交互测试。

这是新论文上的小规模构造报告测试，参考标注由代理核对原文制定，未经双人独立
人工标注；不能将本次一致率直接解释为自然用户报告的总体准确率。

### 两条支持漏判

- **RX01**：ResNeXt-50（32×4d）在 ImageNet-1K、224×224 单裁剪下的
  top-1 错误率 22.2%。候选包含正文数值和表注，但缺少 `p6_b24` 的表头与行，
  因而不能明确其指标是 top-1。二次判定曾给出支持，引用复核正确地拒绝放行。
- **LN03**：训练 1M 次的 Ours + LN 在 MR 上准确率 79.5%。候选包含数值行和
  训练设置，却没有 `p8_b51` 的任务列标题，不能将 79.5 绑定到 MR；最终 ABSTAIN。

两个页面的表题均位于数据之后。当前表格扩展从命中的表题向后扫描，难以恢复
前面的表头与数据。不能通过放宽引用完整性要求来解决，应补齐所需原文结构。

### 两条标签正确但“矛盾”引用不充分

- **SE04**：报告把 r=8 的 top-1 写成 23.40%，原文实际为 23.19%。
- **SE05**：报告把 original ResNet-50 的 top-1 写成 23.29%，原文实际为 24.80%。

两条结果都只引用了 `p8_b6` 的 Table 5 说明。它只解释任务、模型及 original
含义，没有任何上述数值；真正的数据块 `p8_b5` 也不在各自候选池中。
候选复审甚至明确指出缺失具体数据行，但其逻辑只允许恢复支持，不会降低既有
负向结论的确定性，最终仍保留原来的 CONTRADICTED 和具体纠正数值。

同一初审批次的 SE01 候选包含完整 Table 5，因此存在跨论断借用信息的可能；
本次不能证明模型内部如何取得数字。可以确定的是：这两条最终判定没有建立
属于本条论断的充分引用链，不能当作证据充分的成功案例。

这也说明不能用“金标块全部召回”代替证据充分性：RX02、SE02、SE03 即使没有
完整召回预先选定的表格块，仍有正文和表注提供等价、可核对的充分证据。

- 两类复审共 18 次请求、67,699 token，占总 token 的 45.8%。这是实际消耗分解，
  没有关闭复审的配对运行，不能宣称其因果收益或成本差。

  阶段耗时为跨并发报告的累计请求时间，不等于整个实验墙钟时间。

## 下一步顺序

1. 给 CONTRADICTED 增加证据完整性门禁：明确引用相同主体、设置下的冲突数值，
   无法建立本条引用链时保留不确定性；不能仅凭合法的 evidence_id 或表题放行。
2. 处理表题位于数据下方、表头与数据分块的召回；保持有界扫描和原文可追溯。
3. 在新的测试集上验证上述改动，再优化复审触发条件与请求耗时。本次样本一旦用于
   修复，就属于已见开发诊断集，不能继续宣称为新的独立泛化验证。
